1核心协议怎么移过来的

安卓原协议分两套 TCP 编码，靠首 4 字节分流。移植时逐项对齐，全部做了字节级对拍验证。

v4 文件收发序列

逐行取自 FileSend.java / FileServer.java：

发送：MAGIC_NUM(4B) → int NEW_VERSION_4(-2) → str deviceJson
      → int FS_SHARE_FILE(1101) → bool encData → str transferJson
      ↔ int 等待应答，必须 == FS_AGREE
      重复: int length + bytes（encData 时 FileCrypto 变换，
            index 按文件内累计偏移）

接收：没有结束标记，按声明的 length 收够即停；length <= 0 即中止
      （取自 FileServer.recvStreamToFile()）

唯一零改动复用的资源

assets/web/** 5 个文件原样搬进 resources/rawfile/web/** —— 网页前端界面完全复用。

2怎么兼容 V5 协议

核心是双代次并存 + 按对端版本号分流。

2.1 双代次并存

旧协议（dataVersion < 4）v4 协议
开头魔数 → DataEnc 包（12B 头）魔数 → 裸 int NEW_VERSION_4 = -2
混淆全段 0x45无混淆
命令在包头里裸 int，写在流里
结构一个包一个命令一条流顺序写多字段，长度由业务字段自带

分流点：LanService.handlePrivateProtocol() 先读 4 字节判代次， 命中 NEW_VERSION_4 转 handleV4()，否则 unshift() 回退旧协议解析。

第一版踩的坑

只做了旧协议：收到 Android 端的 FF FF FF FE 会按 12 字节包头解析出乱码命令码， 然后当「未知协议流量」断开 —— 现象是能发现设备，但一发文件就失败。

2.2 按对端版本号分流

新增字段按对端广播的 dataVersion 分流，协议侧与网页侧各自独立：

  • 收尾 ack 字节数：1.35 与 1.0 不同 ⇒ 按版本分别处理
  • 设备列表显示版本徽章（V3 / V4 / V5），并带进消息页胶囊与发文件弹窗
  • 已发文件改用握手 UUID 反查发现表判活，不依赖传输层状态

2.3 V5 传输层：三条平行路径

路径实现场景
单文件V5Transfer.recvBody协议侧大文件
分片V5Transfer 的 SegPart协议侧小文件（1.35 对小文件也切 16 片）
网页MultipartStream.closePart浏览器上传

三条路径是平行实现

新增任何逻辑（改名、纠错、记账）必须三条都接入 —— 历史上曾漏了分片路径，连续三版没测到， 而小文件恰恰走分片。

3网页接收怎么实现

安卓用 HttpServer-1.9.57.jar，鸿蒙无等价库 ⇒ 自研三个模块， 与私有协议共用同一个 5856 端口，按首字节分流。

模块构成

net/HttpProtocol.ets（HTTP 解析） + net/WsProtocol.ets（WebSocket 帧） + net/HttpRouter.ets（路由）

3.2 鉴权流程

  1. 网页端连上后先 POST /checkPass，每 2 秒轮询一次直到手机端确认
  2. 密码存 preferences（lanshare_web），与原 App 共用同一文件
  3. 开启「网页免确认」后，新客户端无需手机端点确认（对应原 Config.WEB_OPEN）
  4. 客户端标识用 mUtil.generateRandomString(6) 同款随机名后缀

3.3 双向上传

网页 → 手机

/uploadFile、/chatUploadFile 走 multipart 解析

手机 → 网页

直推原文件，零落盘（连沙箱副本也不要）

批量：多文件打包完即删沙箱副本。

⛔ 能力缺失

「已安装应用列表 / 分享 APK」整块无法保留 —— 三方应用不能枚举其它应用 （GET_BUNDLE_INFO_PRIVILEGED 仅对系统应用开放），也读不到其它应用的安装包（沙箱隔离）。

4UI 上多了哪些新功能

安卓原项目 62 个 layout + Fragment/Adapter 体系，在鸿蒙侧统一改为 ArkUI 声明式组件（pages/Index.ets，8086 行）。

⚠️ 对齐说明

安卓有消息页，在底部 tab 里叫「记录」（strings.xml 里的 record）， 实现是 FragmentChat（919 行）+ ChatAdapter + MessageMediaContent。 下表列的是鸿蒙版相对它新增或显著增强的部分，不是「安卓没有」。

4.6 设备发现

能力说明
设备列表显示版本徽章（V3 / V4 / V5）
下线更快换掉判死模型：向对端 5856 建 TCP 复核连接（不发任何字节就关），连不上连续 2 次即判死 ⇒ 2~3s 消失（原 8~15s）
主动巡检1s 巡检 sweepDevices() —— 离线是「超时」判定，那一刻没有任何事件，不主动巡检只能等下一次别人发包
发现加速收到对方 UDP_GET_DEVICES 探测立即单播应答（原双方各等 5s 周期）；启动时 burst 补探（0.7s / 1.8s 各一轮）
多设备选择多台在线时「+」弹窗选设备
