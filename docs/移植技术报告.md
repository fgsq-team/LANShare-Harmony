# LANShare 安卓 → 鸿蒙移植：核心实现说明

> v5.1.71　2026-10-05
> 本文只讲四件事：**核心协议怎么移过来** / **怎么兼容 V5** / **网页接收怎么实现** / **UI 多了哪些新功能**

---

## 一、核心协议怎么移过来的

安卓原协议分**两套 TCP 编码**，靠首 4 字节分流。移植时逐项对齐，全部做了字节级对拍。

| 协议要素 | 安卓原实现 | 鸿蒙实现 | 对拍 |
|---|---|---|---|
| 12 字节包头（cmd/count/length 大端） | `DataEnc` / `DataDec` | `core/DataPacket.ets` | ✅ |
| `0x45` 混淆层 `(b-1)^0x45` / `(b^0x45)+1` | 同上 | 同上 | ✅ |
| UDP 魔数前缀 `0x66677371` | `UDPTools.sendData` | `DataPacket.encodeUdp()` | ✅ |
| 字符串 `4 字节长度 + UTF-8`，null = -1 | `putString` | 同上 | ✅ |
| **大端 / 小端** | Java 大端 | **JS 原生小端 ⇒ 全部手写大端位移** | ✅ |
| 单端口三协议分流 | `LANService` 1838-1857 | `LanTcpServer.dispatch()` | ✅ |
| 设备平台代号 `HARMONY_OS = 6` | `Device.java` | `DeviceMode.HARMONY_OS` | ✅ **原协议已预留** |
| 设备 JSON 字段名（含原拼写 `devBrotIP` / `uniqueUUid`） | `Device.toJsonObject` | `core/DeviceCodec.ets` | ✅ 逐字段核对 |

**v4 文件收发序列**（逐行取自 `FileSend.java` / `FileServer.java`）：

```
发送：MAGIC_NUM(4B) → int NEW_VERSION_4(-2) → str deviceJson
      → int FS_SHARE_FILE(1101) → bool encData → str transferJson
      ↔ int 等待应答，必须 == FS_AGREE
      重复: int length + bytes（encData 时 FileCrypto 变换，index 按文件内累计偏移）

接收：没有结束标记，按声明的 length 收够即停；length <= 0 即中止
      （取自 FileServer.recvStreamToFile()）
```

**唯一零改动复用的资源**：`assets/web/**` 5 个文件原样搬进 `resources/rawfile/web/**`，
网页前端界面完全复用。

## 二、怎么兼容 V5 协议

### 2.1 双代次并存

TCP 上两套编码靠首 4 字节分流：

| | 旧协议（`dataVersion < 4`） | **v4 协议** |
|---|---|---|
| 开头 | 魔数 → DataEnc 包（12B 头） | 魔数 → **裸 int `NEW_VERSION_4 = -2`** |
| 混淆 | 全段 `0x45` | **无混淆** |
| 命令 | 在包头里 | 裸 int，写在流里 |
| 结构 | 一个包一个命令 | **一条流顺序写多字段**，长度由业务字段自带 |

**分流点**：`LanService.handlePrivateProtocol()` 先读 4 字节判代次，
命中 `NEW_VERSION_4` 转 `handleV4()`，否则 `unshift()` 回退旧协议解析。

⚠️ 第一版只做了旧协议：收到 Android 端的 `FF FF FF FE` 会按 12 字节包头解析出乱码命令码，
然后当「未知协议流量」断开 —— 现象是**能发现设备，但一发文件就失败**。

### 2.2 按对端版本号分流

新增字段按对端广播的 `dataVersion` 分流，**协议侧与网页侧各自独立**：

- 收尾 ack 字节数：1.35 与 1.0 不同 ⇒ 按版本分别处理
- 设备列表显示**版本徽章**（V3 / V4 / V5），并带进消息页胶囊与发文件弹窗
- 已发文件改用**握手 UUID 反查发现表**判活，不依赖传输层状态

### 2.3 V5 传输层

| 路径 | 实现 | 场景 |
|---|---|---|
| 单文件 | `V5Transfer.recvBody` | 协议侧大文件 |
| 分片 | `V5Transfer` 的 `SegPart` | 协议侧小文件（1.35 对小文件也切 16 片） |
| 网页 | `MultipartStream.closePart` | 浏览器上传 |

**三条路径是平行实现** —— 新增任何逻辑（改名、纠错、记账）必须三条都接入。

## 三、网页接收怎么实现

### 3.1 替代方案

安卓用 `libs/HttpServer-1.9.57.jar`，鸿蒙无等价库 ⇒ **自研** `net/HttpProtocol.ets`（HTTP 解析）
+ `net/WsProtocol.ets`（WebSocket 帧）+ `net/HttpRouter.ets`（路由），
在 `LanTcpServer` 的 accept 循环里与私有协议**共用同一个 5856 端口**，按首字节分流。

### 3.2 路由表（与原 `LHttpServer.java` 一一对应）

| 路径 | 原实现 | 鸿蒙侧 |
|---|---|---|
| `GET /` | 返回 `assets/web/lanshare.html` | `rawfile/web/lanshare.html` ✅ 复用 |
| `GET /css/* /js/* /images/*` | 静态资源 | `rawfile/web/**` ✅ 复用 |
| `GET /favicon.ico` | 静态资源 | rawfile 内无此文件，返回 204 |
| `GET /files?dir=` | 列目录，返回 JSON | 沙箱 + 用户授权目录 |
| `GET /file/*` | 单文件下载，支持 Range | 同左 |
| `GET /media` | 媒体（图片/视频）列表 | ✅ |
| `GET /wss` | WebSocket 升级 | `WsProtocol` |
| `POST /checkPass` | 校验网页端访问密码 | `preferences` |
| `POST /initConfig` | 网页端拉取初始配置 | 同左 |
| `POST /updateWebName` | 网页端修改设备名 | 同左 |
| `POST /uploadFile` | 网页端上传单个文件 | ✅ `MultipartStream` |
| `POST /chatUploadFile` | 网页端聊天上传 | ✅ |
| `GET /compressFiles` `/downloadZipFile` | 打包下载 | ✅ `zlib` |
| `GET /apps` `/appicon` `/apkfile/*` `/drawable` | 已装应用列表 + APK 下载 | ⛔ 鸿蒙不开放 |

### 3.3 鉴权流程

1. 网页端连上后先 `POST /checkPass`，每 2 秒轮询一次直到手机端确认
2. 密码存 `preferences`（`lanshare_web`），与原 App 共用同一文件
3. 开启「网页免确认」后，新客户端无需手机端点确认（对应原 `Config.WEB_OPEN`）
4. 客户端标识用 `mUtil.generateRandomString(6)` 同款随机名后缀

### 3.4 双向上传

- **网页 → 手机**：`/uploadFile`、`/chatUploadFile` 走 multipart 解析
- **手机 → 网页**：直推原文件，**零落盘**（连沙箱副本也不要）
- 批量：多文件打包完即删沙箱副本

### 3.5 ⛔ 能力缺失

「已安装应用列表 / 分享 APK」整块无法保留 —— 三方应用不能枚举其它应用
（`GET_BUNDLE_INFO_PRIVILEGED` 仅对系统应用开放），也读不到其它应用的安装包（沙箱隔离）。

## 四、UI 上多了哪些新功能

安卓原项目 62 个 `layout` + Fragment/Adapter 体系，在鸿蒙侧统一改为 ArkUI 声明式组件
（`pages/Index.ets`，8086 行）。

⚠️ **对齐说明**：安卓**有**消息页，在底部 tab 里叫「**记录**」（`strings.xml` 里的 `record`），
实现是 `FragmentChat`（919 行）+ `ChatAdapter` + `MessageMediaContent`。
下表列的是鸿蒙版相对它**新增或显著增强**的部分，不是「安卓没有」。

### 4.1 整体交互形态

| 能力 | 说明 |
|---|---|
| **打开即共享** | `aboutToAppear` 自动 `startSharing`，无「开始共享」按钮；仅失败时露出「重试」 |
| **四个页签** | 共享 / 消息 / 文件 / （日志已并入共享页底部「复制日志」） |
| **不做后台保活** | 退到后台即停服、回前台自动恢复。页面文案明确提示「保持本页在前台」 |
| **防息屏** | `setWindowKeepScreenOn(true)`，**不需要任何权限**（替代安卓的 `WakeLock`） |
| **本机名称可改** | 共享页「运行模式」卡加「本机名称」行，就地编辑写入 `preferences`，下一轮 UDP 广播即带新名；编辑态可「恢复默认」 |
| **二维码** | 访问地址旁用 ArkUI **内建 `QRCode` 组件**渲染（无需三方库） |
| **返回键语义** | `onBackPress()`：多选态 → 取消多选；弹窗 → 关弹窗；都不是才交还系统 |

### 4.2 消息页（安卓「记录 tab」的增强版）

| 能力 | 安卓「记录 tab」 | 鸿蒙增强 |
|---|---|---|
| 双向文字消息 | 有 | 双方互发，走 `LanService.sendTextMessage` |
| **消息内缩略图** | **布局有控件但没绑数据** —— `chat_left/right_media_item.xml` 定义了 `chat_media_image`，但 `MediaMsgHolder.media` 这个 ImageView 全程无 `setImage` 调用，`ChatAdapter` 只设了大小 / 进度 / 时长 / 状态 | 缩略图真正加载；多张自动聚合成宫格 |
| **同步本机删除状态** | 无 —— 气泡状态只有传输成功 / 失败 / 进度 | 相册资产删除探测（**每张图一条索引**，删一张不再全批失效），界面同步显示「已删除」 |
| **在记录页直接发文件** | 无 —— 发送入口在首页设备行 | 发送入口收敛为输入框右侧「+」，`bindMenu` 弹「相册 / 文件」，**在记录页内闭环** |
| 聊天气泡聚合 | 无（一张一条消息） | 多张聚合成**一个气泡**（宫格），但**记账仍每张一条**（显示聚合 ≠ 记账聚合） |
| 文件消息卡片 | 无 | `ChatMessage` 新增 `kind`（`text`/`file`）。传输**成功**（`done && ok`）时插一条记录，内容为文件名（多发为「N 个文件」），点击跳文件页。⚠️ 失败不插 |
| 气泡信息 | 仅文件名 | 文件大小 + 平均速度 |
| 发送目标选择 | 需回首页 | 页签顶部设备胶囊直接切；设备行显示**版本徽章**（V3 / V4 / V5） |
| 消息持久化 | 有（`MesssageDButil`） | 落盘 `${filesDir}/chat_history.json`（MiniJson 手写序列化），启动恢复；「清空」连持久化一起清 |
| 视频角标 | 时长 | 纯文字 `VIDEO` 角标（不用 ▶ 图标，避免不可见） |

### 4.3 文件页（独立页签）

| 能力 | 说明 |
|---|---|
| 独立页签 | 「接收到的文件」独立成页，切到该页自动刷新 |
| **48×48 缩略图** | 按扩展名识别图片，`fileUri.getUriFromPath()` 取沙箱 URI，配 `sourceSize(96)` 压解码尺寸（不压的话 40 张原图会整张解进内存） |
| **点开看大图** | 全屏预览：双指缩放 / 双击复位 / 放大后可拖动 / 返回退出 |
| **批量另存为** | 长按进多选 → 顶部「已选 N / 全选 / 取消」→ 底部「另存为(N) / 删除(N)」。`ExportService.saveMany` 一次弹窗处理多文件 |
| 删单个 + 删一批 | 行内「删除」按钮（删一个）+ 长按多选（删一批）并存 |
| 自绘删除确认框 | 系统 `showDialog` 的 title 字号固定、不按内容折行 ⇒ 改为自绘：标题固定 16fp，文件名单独一块 13fp + `maxLines(5)` + `BREAK_ALL`，多长名字都能整段折行看全 |
| 清空 + 路径守卫 | 「清空」走 `ExportService.deleteAll`，带路径守卫 |
| 文件名自适应 | `maxLines(2)` + `wordBreak(BREAK_ALL)`。⚠️ 不能叠 `lineHeight` —— 它同时约束行高与组件高度，正是「两行出不来」的原因 |

### 4.4 传输进度浮层

| 能力 | 说明 |
|---|---|
| 实时速度 | 瞬时速度（EMA）+ 平均速度**两道门限分开**（不是同一语义） |
| 文件名两行 | 长文件名超长时折两行，顶部带 Linear 进度条 |
| 完成态 | 完成停转 + 换色 + 对勾旁显示「完成」+ 5 秒自动收 |
| 独立提示通道 | 完成提示走 toast 独立通道，不与进度浮层抢状态 |
| 传输中地球 | 补回传输中的动效 |

### 4.5 相册与存相册

| 能力 | 说明 |
|---|---|
| **相册选择器** | 走 `PhotoViewPicker`，**URI 永久授权：无需权限、无需先复制到沙箱** |
| 双选择器 | 设备行两个按钮「相册」/「文件」并列 |
| 批量存相册 | 消息多选态加「存相册 (N)」 |
| 自动存相册 | 可开关；相册资产删除探测（每张图一条索引，删一张不再全批失效） |
| 沙箱自动清理 | 另存为 / 发到网页端后自动删沙箱副本 |
| **魔数纠错** | 按文件头判断真实类型，纠正错后缀。口径 = **只纠正错后缀，不给无后缀文件硬加后缀**；同类型等价（`a.jpeg` 与 `a.jpg`）不动 |

### 4.6 设备发现

| 能力 | 说明 |
|---|---|
| 设备列表 | 显示**版本徽章**（V3/V4/V5） |
| 下线更快 | 换掉判死模型：向对端 5856 建 TCP 复核连接（**不发任何字节**就关），连不上连续 2 次即判死 ⇒ **2~3s 消失**（原 8~15s） |
| 主动巡检 | 1s 巡检 `sweepDevices()` —— 离线是「超时」判定，那一刻**没有任何事件**，不主动巡检只能等下一次别人发包 |
| 发现加速 | 收到对方 `UDP_GET_DEVICES` 探测**立即单播应答**（原双方各等 5s 周期，最坏慢一整拍）；启动时 burst 补探（0.7s / 1.8s 各一轮） |
| 多设备选择 | 多台在线时「+」弹窗选设备 |
| 相册选择器 | 选相册与选文件并列 |
